| 항목 | 내용 |

| 문서 상태 | v1.1 반영 (2026-08-21) |

## 1. 배경과 문제

무언가를 뽑아야 하는 자리는 자주 생긴다. 발표 순서, 청소 당번, 경품, 팀 나누기.
이때 흔히 쓰는 방법에는 각각 아쉬움이 있다.

- **가위바위보·제비뽑기**: 준비가 번거롭고, 사람이 많으면 오래 걸린다.
- **랜덤 숫자 뽑기 사이트**: 결과가 한 번에 튀어나와서 납득의 과정이 없다. "왜 하필 나야"라는
  말이 나오면 반박할 재료가 없다.
- **돌림판 룰렛**: 과정은 보이지만 몇 초면 끝나고, 인원이 많아지면 칸이 좁아 읽기 어렵다.

핵심 문제는 **공정성 자체보다 공정하다는 느낌**이다. 난수 한 번으로 정해진 결과는 검증할 수도
즐길 수도 없다. 반면 구슬이 굴러 내려가 순서대로 결승선을 통과하는 장면은, 모두가 같은 화면을
20~30초 함께 보면서 결과를 받아들이게 만든다. 뽑기를 **이벤트로 만드는 것**이 이 제품의 역할이다.

## 2. 목표와 비목표

### 목표

1. 이름만 붙여넣으면 30초 안에 추첨이 끝난다. 회원가입도, 설정도 없다.
2. 결과가 나오는 과정을 모두가 함께 본다. 지켜보는 재미가 있어야 한다.
3. 참가자 목록 순서가 결과에 영향을 주지 않는다. 그리고 그렇다고 설명할 수 있어야 한다.
4. 교실 화면, 회의실 프로젝터, 손에 든 휴대폰 어디서나 그대로 쓸 수 있다.

### 비목표 (v1에서 하지 않는 것)

- 계정, 로그인, 추첨 기록 서버 저장 — 이 앱은 서버 없이 브라우저에서만 돈다.
- 실시간 멀티플레이(각자 기기에서 같은 경기를 함께 보기).
- 상금·응모권처럼 법적 책임이 따르는 추첨의 감사(audit) 기능.
- 코스 직접 만들기(에디터).

## 3. 사용자와 시나리오

| 사용자 | 상황 | 필요한 것 |
| --- | --- | --- |
| 교사 | 25명 학급에서 발표 순서를 정한다 | 명단 붙여넣기, 큰 화면에서 읽히는 이름, 전체 순위 |
| 모임 진행자 | 회식 자리에서 경품 3개를 뽑는다 | 당첨 인원 지정, 결과창, 결과 복사 |
| 팀 리더 | 원격 회의에서 당번을 정한다 | 참가자 목록이 담긴 링크 공유 |
| 친구들 | 누가 계산할지 정한다 | 휴대폰 한 대로 바로 실행, 소리와 함께 관전 |

**핵심 흐름**: 이름 붙여넣기 → 당첨 인원 확인 → 시작 → 20~30초 관전 → 결과창 → (필요하면) 한 판 더.

## 4. v1 요구사항과 구현 결과

전부 구현·검증 완료. 괄호 안은 실제 확인 방법이다.

### 4.1 참가자 입력 (P0)

- 한 줄에 한 명. 쉼표로도 구분한다.
- `영희*3`, `영희/3` — 같은 이름을 여러 개 넣는다. 확률 가중치를 이렇게 준다.
- 최대 120개. 그 이상은 화면에서 이름을 읽을 수 없고 성능도 떨어진다.
- 입력한 목록은 브라우저에 저장되어 다음에 열 때 그대로 남는다.
- 목록 섞기, 비우기 버튼.

### 4.2 추첨 실행 (P0)

- 당첨 인원은 1명부터 참가자 수까지 지정한다. 지정한 등수까지 도착하면 결과창이 뜬다.
- 코스 3종: 지그재그(기본), 핀볼, 바람개비. 코스마다 회전 막대·못·깔때기 배치가 다르다.
- 모든 코스는 끝에서 좁은 목을 하나씩 통과하게 되어 있다. 마지막까지 순위가 갈린다.

### 4.3 공정성 (P0)

추첨 앱에서 이건 기능이 아니라 전제다.

- **출발 자리를 매 경기 무작위로 섞는다.** 목록 순서와 유불리를 끊기 위한 조치다.
  (섞기 전 측정에서 지그재그 코스 오른쪽 끝 자리가 40판 중 28판을 이겼다. 자리 자체의 유불리는
  코스 설계로 완전히 없애기 어렵기 때문에, 자리 배정을 섞는 쪽으로 해결했다.)
- **경기는 끝까지 진행된다.** 모든 구슬이 결승선을 통과하고, 전체 순위가 남는다.
  (코스 3종 × 8명/40명 × 20판 = 120판 시뮬레이션에서 미완주 0건.)
- **끼임 구조.** 못과 벽 사이에 구슬이 끼면 최고 도달 지점이 갱신되지 않는 것으로 감지해서,
  먼저 살짝 밀고 그래도 안 되면 안쪽으로 조금 옮긴다. 특정 구슬이 영원히 지는 일이 없어야 한다.

### 4.4 관전 (P0/P1)

- 카메라가 선두를 따라가되, 뒤따르는 무리까지 담기도록 배율을 자동 조절한다. (P0)
- 확대 보기 — 선두 구슬에 붙어서 본다. (P1)
- 속도 ×1 / ×2 / ×4, 일시정지. (P1)
- 결과 바로 보기 — 남은 경기를 즉시 계산해서 결과만 본다. 시간이 없을 때를 위한 탈출구다. (P1)
- 상단에 경과 시간, 남은 구슬 수, 현재 1~3위. (P1)
- 충돌음·도착음·당첨 팡파르. 파일 없이 WebAudio로 만들고, 끌 수 있다. (P2)

### 4.5 결과 (P0)

- 결과창에 당첨자를 등수 순으로 보여준다. "끝까지 보기"로 나머지 경기를 계속 볼 수 있다.
- 옆 패널에 도착 순서대로 전체 순위와 기록(초)이 쌓인다.
- 당첨자 목록 복사, 전체 순위 복사.
- "한 판 더" — 같은 참가자로 새 경기를 바로 시작한다.

### 4.6 공유 (P1)

- 참가자 목록·당첨 인원·코스를 주소 해시에 담은 링크를 복사한다. 서버 없이 동작한다.

### 4.7 비기능 요구사항

| 항목 | 기준 | 결과 |
| --- | --- | --- |
| 한 판 소요 시간 | 1등이 30초 안에 정해진다 | 코스별 14~28초 |
| 전원 완주 | 60초 내외 | 평균 29~61초 (40명 기준) |
| 프레임 | 60fps 유지 | 40개 구슬에서 60.3fps |
| 화면 | 휴대폰(390px)부터 프로젝터까지 | 세로/가로 레이아웃 분리 확인 |
| 서버 | 없음. 데이터는 브라우저를 벗어나지 않는다 | 정적 페이지, 저장은 localStorage |

## 5. 측정할 것

서버가 없어 사용 로그를 모으지 않는다. 대신 코스를 수정할 때마다 다음을 확인한다
(`docs/구슬-레이스-룰렛.md`의 시뮬레이션 스크립트).

- 미완주 0건 — 끼여서 못 들어오는 구슬이 없어야 한다.
- 1등 결정 시간 30초 이내 — 지루해지는 경계선.
- 출발 자리별 평균 순위 편차 — 코스 자체의 유불리를 보는 값. 자리 섞기로 가리지만 작을수록 좋다.

## 6. v1.1에서 구현한 것

v1 문서에서 "다음 후보"로 적어둔 항목을 모두 구현했다.

| 항목 | 어떻게 |
| --- | --- |
| 꼴찌 뽑기 | 뽑는 방식에 **뒤에서**를 추가. 끝까지 달린 뒤 꼴찌부터 세어 당첨자를 정한다. |
| 팀 나누기 | 뽑는 방식에 **팀 나누기**를 추가. 도착 순서대로 돌아가며 팀에 넣어(1등 1팀, 2등 2팀…) 인원이 저절로 고르게 된다. |
| 결과 이미지 저장 | 결과창에서 PNG 한 장으로 저장. 화면 캡처가 아니라 캔버스에 직접 그려서 잘림이 없다. |
| 키보드·스크린리더 | 스페이스·R·S·Z·M 단축키와 ESC, 또렷한 초점 표시, 경기 시작·상위 도착·최종 결과를 읽어주는 `aria-live` 안내. |
| 이름 색 지정 | `영희#f43f5e` 문법. 지정하지 않은 이름은 기존처럼 자동으로 색을 받는다. |
| 코스 랜덤 선택 | 코스에 **랜덤** 추가. 매 판 무작위로 고르고 어떤 코스인지 표시한다. |
| 엑셀·CSV 명단 불러오기 | 첫 열을 이름으로 읽고 머리글 행은 버린다. 엑셀 파서는 파일을 고를 때만 따로 받아온다. |

설계상 유의한 점 두 가지.

- **뽑는 방식을 바꾸면 경기를 새로 준비한다.** 앞에서 뽑기는 정한 등수에서 경기를 멈출 수 있어,
  그 결과를 뒤에서 뽑기나 팀 나누기에 그대로 쓸 수 없기 때문이다.
- **저장 파일명은 아스키로 둔다.** 한글 파일명을 흘리는 브라우저가 있어 `marble-race-날짜-시각.png` 형식을 쓴다.

## 8. 리스크와 결정 사항

- **물리 엔진 의존(planck).** 결정: 직접 구현하지 않고 검증된 Box2D 포팅을 쓴다. 구슬끼리 쌓이고
  회전체에 부딪히는 상황에서 안정성이 직접 만든 것과 차이가 크다. 번들 240KB(gzip 57KB)는 감수한다.
- **결과가 결정론적이지 않다.** 같은 참가자로 다시 돌리면 결과가 달라진다. 이건 의도다.
  다만 "아까 그 경기"를 재현할 수는 없으므로, 분쟁 소지가 있는 추첨에는 결과 복사를 안내한다.
- **120명 상한.** 그 이상은 이름이 읽히지 않는다. 대규모 추첨은 이 제품의 대상이 아니다.
- **자동 구조 로직이 결과에 개입한다.** 낀 구슬을 옮기는 처리는 그 구슬에게 유리하게도, 불리하게도
  작용할 수 있다. 개입 없이 영원히 못 들어오는 것보다는 낫다고 판단했다. 개입 빈도를 낮추는 방향은
  코스 설계 쪽에서 계속 손본다.
